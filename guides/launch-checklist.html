바이브코딩 앱 출시 전 체크리스트 — 막히는 곳 10가지

코드는 다 짰는데 출시가 안 될 때, 막고 있는 건 대부분 코드 바깥입니다. 예약형 서비스 하나를 79개 항목으로 점검했더니 40개가 출시를 막고 있었고, 그중 권한·동시성 같은 보안 코드 문제는 0개였습니다.

요약
배포 실물부터 만드세요. 결제사 심사, 웹훅 주소, 소셜 로그인 콘솔, 메일 도메인 인증이 전부 실 도메인을 요구합니다. 그다음 결제, 환불 규정, 운영 설정, 로그인 경로, 약관, 관측·백업 순서로 확인하면 됩니다.

01배포 실물 — 도메인·HTTPS·헬스체크

운영 도메인과 HTTPS가 있는 실제 배포 환경이 없으면 다른 준비가 진행되지 않습니다. 개발과 운영이 같은 데이터베이스를 쓰는 경우도 흔합니다.

10분 확인운영 주소로 접속되는가 · 배포 설정의 DB 주소가 개발용과 다른가 · 헬스체크가 DB 연결까지 확인하는가 · 이전 버전으로 되돌리는 방법이 있는가

02결제 — 테스트 키 다음 단계

테스트 결제가 된다고 결제가 끝난 게 아닙니다. 운영 키로 바꾸기 전에 세 가지가 필요합니다.

  • 웹훅 서명 검증 — 웹훅 본문을 그대로 믿지 않고 결제사의 서명·시크릿으로 확인하는가
  • 중복 반영 방지 — 같은 결제 알림이 두 번 와도 주문이 한 번만 확정되는가(결제 키에 유니크 제약)
  • 돌아오지 않는 고객 — 결제 후 창을 닫아도 서버가 결제 조회로 확정하는가

자세히: 결제 웹훅 안전하게 받기 — 위조·중복·순서·재전송

03환불 규정 — 세 군데가 같은가

약관, 결제 화면, 코드에 적힌 환불 규정이 서로 다른 경우가 많습니다. 예를 들어 약관은 "3일 전까지 전액", 화면은 "하루 전까지", 코드는 기한 없이 전액 환불하는 식입니다.

10분 확인세 곳의 환불 기한·수수료를 표로 나란히 적어 보기 · 환불을 실제로 누가 어떤 화면에서 처리하는가

04운영 설정 — 빠진 한 줄

코드가 읽는 환경변수가 배포 설정에 빠져 있는데도 앱이 그대로 뜨면, 운영에서만 이상하게 동작합니다. 설정 한 줄 때문에 모든 요청이 403이 되는 구성도 있습니다.

10분 확인.env.example 의 키와 배포 설정의 키를 한 줄씩 대조 · 필수 값이 없으면 부팅을 멈추게 하기 · 테스트용 결제·시드가 운영에서 꺼지는가

05가입·로그인 경로

소셜 로그인은 콘솔에 운영 도메인의 리다이렉트 주소를 따로 등록해야 합니다. 개발 주소만 등록돼 있으면 운영에서만 실패합니다. 메일·문자 인증도 운영용 발송 공급자가 있어야 합니다.

06약관·처리방침·사업자 정보

사업자 정보 칸이 비어 있거나, 결제를 하는데 약관에는 "결제를 제공하지 않는다"고 적힌 경우를 자주 봅니다. 처리방침은 실제로 받는 항목과 위탁사(호스팅·결제·메일)를 적어야 합니다. 결제를 받는다면 화면 하단의 상호·대표·사업자번호·통신판매업 신고번호도 필요합니다.

법률 자문이 아니라 확인할 목록입니다. 최종 문안은 전문가 확인을 권합니다.

07관측·백업·비용

장애가 나도 알 방법이 없거나, 되돌릴 백업이 없는 경우입니다. 백업은 복원해 본 적이 있어야 백업입니다.

10분 확인에러가 나면 누가 어떻게 아는가 · DB 백업 주기와 마지막 복원 연습 · 클라우드 예산 알람

08목업·시안 숨기기

샘플 데이터 화면, "준비 중" 버튼, 고정 숫자 대시보드가 실제 사용자에게 보이면 신뢰를 잃습니다. 메뉴에서 연결된 미완성 화면을 찾아 숨기세요.

09운영자가 쓸 수 있는가

고객 쪽 화면은 다 있는데, 운영자가 환불·취소·신고 처리·첫 관리자 계정 만들기를 할 화면이나 명령이 없는 경우입니다.

10로그 개인정보·복구 경로

요청 로그에 이메일·전화번호·토큰이 그대로 찍히는지, 비밀번호 재설정 같은 복구 경로가 역할마다 있는지 확인합니다.
