1시크릿

1.1저장소와 전 히스토리에 시크릿이 없다차단확인: git ls-files 에 .env* 는 예시 파일만 · gitleaks 를 전 히스토리로 1회(CI 에 스텝만 있고 돈 적이 없는지도 본다)
1.2프론트 번들·HTML/RSC 응답에 서버 시크릿이 없다차단확인: 서버 비밀 변수에 센티널을 넣고 빌드 → 정적 산출물·응답 grep 0건 · 공개 키(지도 등)는 도메인 제한이 방어인지
1.3로그 채널별(앱 로그 · DB 오류 로그 · 프록시 접근 로그)로 개인정보·토큰이 찍히지 않는다차단확인: 같은 이메일로 가입 2회 → DB 오류 로그의 파라미터 · 재설정/초대 링크가 쿼리 토큰이면 접근 로그에 남는다(fragment 로) · 요청 본문을 찍는 미들웨어 0
1.4프로덕션 시크릿 주입 경로가 실제로 있고(스크립트·Secrets Manager), 개발 기본값·누락이면 부팅이 거부된다차단확인: 배포 설정의 필수 변수 목록 ↔ 저장소 경로 대조 dry-run · 빈 env 로 NODE_ENV=production 부팅 → 거부 · 부팅 검사를 부르는 spec 이 있나
1.5키 회전 절차가 키마다 있고(세션·인증번호·MFA·큐 페이로드·외부 시크릿) 한 번 리허설했다권장확인: 이전 키 슬롯 유무 · 절차 문서 · 로컬 리허설(A → B+PREVIOUS → 제거)

2접근 제어

2.1모든 API 라우트가 권한을 명시하고 미명시는 기본 거부다 (Supabase: 모든 표 RLS ON + 정책 / 자체 백엔드: 전역 가드)차단확인: 라우트 데코레이터·정책 전수 대조 · 미명시 라우트를 거부하는 테스트
2.2소유자·테넌트 격리 — 남의 id 로 조회·수정·취소하면 404/403 (IDOR)차단확인: 다른 사용자 세션으로 상대 id 직접 호출 · 테넌트 쿼리에 WHERE 가 있는지 불변식(핸들러 전수가 테넌트 id 를 쓰는지)
2.3서버 액션·라우트 핸들러·엣지 함수가 API 가드를 우회해 DB 를 직접 만지지 않는다차단확인: 웹 앱에 DB 드라이버 import 0 · 호출이 단일 클라이언트 함수(쿠키·Origin 동봉)로 모이는지 spec
2.4관리자 응답이 개인정보를 가리고, 열람·검색이 기록된다권장확인: 계약(타입)에 원문 필드 없음 · 열람 감사 행
2.5스토리지 버킷은 전부 비공개, 읽기는 서명 URL/CDN, 업로드 키는 서버가 만든다차단확인: Block Public Access · 정책 · 비인증 목록/GET 403 · 서명 변조 smoke(실 스토리지에서 — 목은 검증 안 함)

3인증

3.1비밀번호는 느린 해시(argon2·scrypt·bcrypt)로만, 가역 저장은 전용 키가 있는 것(TOTP 비밀 등)만차단확인: 해시 생성 지점이 한 문(單門)인지 · 비밀번호 열이 해시 문자열만
3.2세션 쿠키 Secure·HttpOnly·SameSite·Domain 없음, 파기·정지가 요청마다 즉시 반영 — HTTPS 가 먼저차단확인: 응답 헤더(TLS 뒤) · 로그아웃·재설정·정지 뒤 옛 쿠키 401 · __Host-/Secure 쿠키는 HTTP 에서 버려진다
3.3인증번호·재설정 토큰은 해시 저장·1회성·만료·시도 횟수 제한·발송 한도(IP 존 + 주소별 백오프)차단확인: 6회째 거부 · 사용한 링크 재사용 거부 · 프록시 존이 발송/확인 경로를 덮는지
3.4운영에서 실제로 동작하는 가입·로그인 경로가 하나 이상 있다 — 메일·문자·소셜 중 공급자가 붙은 것차단확인: 운영 설정으로 각 경로 끝까지 1회 · "준비 중" 으로 잠긴 경로를 뺀 뒤 남는 것
3.5모든 역할(고객·판매자·직원·관리자)에 비밀번호 복구와 계정 잠금 경로가 닫혀 있다차단확인: 역할별로 재설정 링크 위치 · 잠금이 모든 로그인 경로(초대 수락 포함)를 세는지
3.6관리자 로그인은 2단계(TOTP) + 잠금, 등록·복구·해제가 운영 환경에서 실행 가능권장확인: TOTP 재사용 거부 · 복구 코드 1회성 · 첫 관리자 계정 생성 명령을 운영에서 돌릴 경로

4입력 검증

4.1모든 쓰기 입력(body·param·query·header)이 스키마/파서를 거치고, 모르는 필드는 거부차단확인: @Body·@Param 류 전수가 파서 호출로 넘어가는지 스크립트 점검 · 모르는 쿼리 키 → 400
4.2수량·금액 경계 — 0·음수·소수·상한·합계 오버플로차단확인: 수량 0·-1·1e9, 가격 최댓값×수량 2 → 400(500 아님)
4.3XSS·SQL 주입 — 위험 API 0건, 바인딩만, 템플릿 보간은 상수·허용 목록차단확인: dangerouslySetInnerHTML·innerHTML·eval grep · ${} 보간식이 상수/허용 목록인지
4.4업로드 — MIME·크기·매직 넘버·픽셀 검증, 키는 서버가 만들고 완료 때 실제 바이트를 다시 본다권장확인: SVG/HTML 위장 파일 → 거부 · 서명 URL 로 다른 키에 쓰기 불가
4.5비정상 입력(잘못된 id·토큰·NUL·거대 본문)이 500 이 아니라 400 이고, 프록시 본문 상한이 API 상한과 맞는다권장확인: 비정상 id 10종 → 5xx 0 · %00 · 프록시 client_max_body_size 가 공개 블록에도 있나

5결제 · 환불 · 동시성

5.1PG 선정·계약이 끝났다 — 사업자·통판 서류, 실 도메인 URL(약관·처리방침·사업자 정보가 떠 있는) 심사차단확인: 계약서 · 테스트 키 · 심사 URL
5.2결제 어댑터가 실 PG 이고, 테스트/목 결제가 운영에서 막혀 있다(경고 아님)차단확인: PAYMENT_GATEWAY=mock 류를 운영에서 부팅 거부 · 결제 화면의 "테스트 결제" 문구가 provider 로 분기
5.3승인 멱등성 · 금액 검증(서버 계산 = 요청 = PG 응답) · 상태 머신(조건부 UPDATE + DB CHECK)차단확인: 같은 키 동시 승인 2회 → 확정 1 · 금액 위변조 → 402 · 불가 전이 → 거부 spec
5.4웹훅 수신 — 서명 검증 · 같은 이벤트 2회 → 1회 반영 · 순서 역전(취소가 승인보다 먼저) · 재전송에 응답차단확인: 수신 엔드포인트 존재 · 중복·역전 spec
5.5고객이 돌아오지 않을 때 끝낼 주체 — 결제 조회 포트 + 멈춘 승인·환불 대기 대사(對査) 작업 + 운영자 알림차단확인: 포트에 조회가 있나 · 대사 잡·알림 · 운영자 화면에서 고아 결제가 보이나
5.6결제 실패 경로(사용자 취소 · 거절 · 결과 불명)와 중복 클릭·뒤로가기가 각각 정확한 상태·안내로 떨어지고 실 PG 테스트 모드 e2e 가 있다차단확인: 3경로 + 더블클릭 + 뒤로가기 e2e · "살아 있는 결제 1건 이하" 제약
5.7취소·환불 규정이 확정되고 코드·약관·결제 전 고지 셋이 같다 — 공정위 소비자분쟁해결기준 대조(업종별 기준 — 이용일 며칠 전까지 전액, 당일은 공제, 판매자 불이행 때 배상)차단확인: 수수료 계산 함수 1곳 ↔ 약관 조항 ↔ 결제 전 문구를 한 표로 · 결제 전 동의 버전이 주문 행에 기록되나
5.8환불 실행 — 전액·부분, PG 호출은 트랜잭션 밖·멱등 재시도, 실패 시 재시도 큐·운영자 알림·고객 "처리 중" 표시와 재시도 길차단확인: 취소 2회 → 환불 1회 · PG 취소 실패 → 환불 대기 → 화면에 재시도 단추
5.9판매자 측 취소·일괄 환불(판매자 사정으로 취소)과 배상 규정, 그리고 환불 요청을 처리할 행위자(판매자 또는 운영자 쓰기 권한)차단확인: 판매자·운영자에게 취소·환불 쓰기 라우트가 있나 · 일괄 환불 재시도
5.10영수증 링크 · 환불 소요 시간·수단 고지 · 환불 내역 조회권장확인: 주문 상세에 영수증·취소 일시·환불 금액 · 수단별 소요 문구
5.11동시성 — DB 가 최종 방어선(부분 유니크·EXCLUDE·CHECK), 판정은 잠금 아래 한 문장, 만료 선점이 자정(自淨)되며, 동시 100 테스트에서 성공 정확히 1 + 불변식 감사 0차단확인: 마이그레이션의 제약 원문 · 선점 코드의 UPDATE/INSERT 문 · 100 동시 × 10회(503 BUSY 도 허용값) · 부하 1회
5.12쓰기 경로(선점·주문) 레이트 리밋 + 사용자당 동시 보유 상한 + 수량으로 파는 상품은 등급별 수량까지권장확인: 프록시 존이 선점 경로를 덮나 · 사용자당 활성 선점 제약 · 등급별 카운터

6환경 분리 · 배포

6.1프로덕션 환경이 실제로 있다(계정·도메인·TLS·80→443·HSTS), 스테이징 또는 PG 테스트 키를 돌릴 곳이 정해져 있다차단확인: 리소스 존재 · 인증서 · curl -I · 스테이징 결정 기록
6.2배포 재현성 — Dockerfile/빌드 스크립트 + .dockerignore(.env* 제외) + 깨끗한 머신 1회차단확인: 새 머신에서 문서대로 빌드·기동 · 이미지에 .env 가 안 들어가나(자동 로드가 개발 값을 조용히 채운다)
6.3배포 절차에 마이그레이션 → 시드/카탈로그 동기화(약관·메뉴) → 헬스체크 → 롤백이 실제 명령으로 있고, dry-run 이 가짜 성공을 알리지 않는다차단확인: 워크플로의 echo/TODO 유무 · dry_run 분기 · 약관 동기화 빠지면 가입이 막히나
6.4환경변수 — 코드가 읽는 키 전부가 예시 파일·배포 설정에 있고, 배포 설정 ↔ 부팅 검사가 테스트로 묶여 드리프트가 조용히 생기지 않는다차단확인: 코드 grep ↔ .env.example ↔ compose/플랫폼 변수 삼자 대조 · 대조 spec
6.5정책값(세션 TTL · 보유 시간 · 수수료 · 잠금 수치 · 보존 기간)이 결정값이고 결정이 저장소에 반영돼 있다차단확인: .env.example 의 "개발 편의값/미정" 주석 · 이슈의 결정 ↔ 코드
6.6국내 리전 · DB 전송 암호화(RDS force_ssl 기본값 확인) · 큐/캐시 저장소 인증권장확인: 리전 설정 · DB 클라이언트 ssl 옵션 · Redis requirepass
6.7개발 시드·목 결제·디버그 도구가 프로덕션에서 거부된다차단확인: 시드 스크립트의 환경 가드 · 목 게이트웨이 부팅 거부

7에러 처리

7.15xx 응답에 스택·SQL 없음 + 전역 catch-all 필터 + 요청 id 가 로그와 응답에차단확인: 강제 DB 에러 응답 본문 · 전역 필터 등록 · x-request-id
7.2화면 — 루트 error/not-found/loading, 빈 상태, 실패 안내가 다음 행동을 말한다(결제 실패·연결 끊김·보상 실패)권장확인: 각 앱 루트에 세 파일 · 주요 목록 빈 상태 · 보상 실패와 "결제 안 됨" 을 다르게 안내하나
7.3외부 호출 타임아웃(PG·스토리지·웹→API)과 재시도 정책(PG 는 멱등 키 있을 때만)차단(PG)확인: 각 클라이언트의 timeout/signal · 재시도 조건
7.4백그라운드 잡 실패 → 재시도·DLQ·알림권장확인: 큐 설정 attempts·backoff · 실패 이벤트 → 알림

8테스트 · CI

8.1머지된 코드가 자동 검증되고 결과가 사람에게 닿으며, CI 분 예산이 실제 사용량 안에 있다차단확인: 최근 실행이 steps 0(쿼터)인지 · 월 사용량 · 알림 워크플로 회수 × 1분 올림
8.2결제·환불·동시성 통합 테스트 + 핵심 흐름 e2e 1벌(실 PG 테스트 모드 포함)차단확인: spec 목록 · 실 PG 키로 1회 녹색
8.3의존성 취약점 — 주기 감사 + 보안 알림(Dependabot alerts) 켜짐권장확인: 감사 결과 high 이상 수치 · 저장소 설정
8.4새 spec 이 실행 목록에 들어가는지 검사(등록부) + 커버리지 숫자후순위확인: 등록부 스크립트 · 누락 spec

9성능

9.1피크 부하 1회 측정(p95·에러율·BUSY 비율) + 느린 쿼리 로그·EXPLAIN권장확인: k6 류 200VU 1분 · log_min_duration_statement
9.2목록 질의 수가 행 수에 비례하지 않고(N+1 없음), FK·조회 조건에 인덱스권장확인: 20행 목록의 질의 수 · FK 선두 열 인덱스 전수
9.3공개 조회 캐싱 · 일반 API 레이트 리밋 · 이미지 파생본/CDN · 큐 메모리 상한권장확인: Cache-Control/revalidate · catch-all 존 · next/image·CDN · maxmemory

10구조

10.1코어 모델이 한 업종 명사로 못박히지 않고, 설계 노트의 "잠정" 이 출시 전 "채택" 으로 갱신된다권장확인: 테이블명 · 노트 상태 줄
10.2미사용·환각 의존성 0 · any/ts-ignore/eslint-disable 0(결제·주문 모듈은 필수) · 중복 컴포넌트후순위확인: knip/depcheck · grep 수
10.3AI 규칙 파일·README 가 코드와 맞는다 — 가장 먼저 낡는 문서후순위확인: 상태 표 숫자 · 기동 순서 · "목업" 서술 표본 3개

11운영 · 모니터링 · 인수인계

11.1에러 추적(국외 이전 고지 포함) + 헬스체크가 DB·큐를 보고 공개 경로로 도달 + 알림 사슬이 1회 울렸다차단확인: SDK 존재·DSN · /health 가 프록시에 라우팅되나 · 알람 강제 발화 → 채팅 도달
11.2백업 보존일 + 복구 리허설 + 롤백 리허설(소요 시간 기록)차단확인: 스냅샷 → 새 인스턴스 → 앱 연결 1회 · 이전 태그 up -d 1회
11.3비용 상한 — 예산 알람(50/80/100%) · 스토리지 자동 확장 상한 · 공개 버킷 트래픽 앞단차단확인: Budgets · RDS 상한 · CDN/요청 제한
11.4로그 보존·검색 · 외부 가동 감시 · 장애 런북(결제·중복 판매·DB 복구·시크릿 회전·관리자 잠금 해제)권장확인: 로그 드라이버 ↔ 문서 · UptimeRobot 류 · 런북 유형별 1쪽
11.5운영 환경에서 관리 명령(첫 관리자 생성 · 잠금 해제 · 카탈로그 동기화)을 실행할 경로가 있다차단확인: compose/플랫폼의 도구 서비스 · 비밀번호가 echo 되지 않나
11.6인수인계 — 실행·배포 문서, 외부 계정 대장(소유자·2FA·복구 메일·결제수단·접근자), 시크릿 대장(위치·회전일)차단확인: 문서 존재 · 빈 머신 30분 기동 실측
11.7비개발자용 운영 절차(입점·정지·환불 처리) + 데이터 복구 가능성(hard delete 에 복구 재료)권장확인: 기획자가 읽고 1건 수행 · 삭제 경로의 감사 행

12출시 품질

12.1목업·시안·가짜 데이터 화면이 실 사용자에게 보이지 않는다 — 기본 메뉴 데이터·대체 이미지·"검수용" 버튼 포함차단확인: mock.ts·고정 데이터 import 전수 · 시드 데이터 · 외부 무작위 이미지
12.2판매자(운영 당사자)가 실제 운영에 필요한 쓰기 — 취소·환불·수령/이용 확인차단확인: 판매자 콘솔의 쓰기 라우트 · 현장 확인 저장
12.3메일·문자 실발송 + 도달(SPF/DKIM/DMARC, 스팸함) + 거래 알림(주문 확인) 템플릿차단확인: 실 발송 1통 원본 보기 spf=pass dkim=pass dmarc=pass · 템플릿 목록
12.4핵심 흐름 5개 수동 통과표(날짜·수행자) + 모바일 실기기 2대(HTTPS 호스트 뒤)차단확인: 통과표 문서 · iOS Safari·Android Chrome

13국내 법규

13.1사업자 정보·통신판매업 번호 footer(전자상거래법 §10) + 개인정보 보호책임자 + 문의 동선(닿을 수 없는 "고객센터" 문구 0)차단확인: footer 전 호스트 · 문의 수단 ↔ 사업자 연락처 일치 · "고객센터" grep
13.2약관 — 구매·지급·청약철회·환급 조항, 거래 구조(중개자 고지 §20), 자리 표시자 0, 효력일 순서(결제 켜기 전 개정판이 효력)차단확인: 시드/문안의 마커 · 조항 유무 · 효력일 ↔ 출시일
13.3처리방침 — 수집 항목(결제·번호)·처리위탁(PG·클라우드·메일·문자)·보존 기간·국외 이전·판매자 제공 항목이 코드 사실과 일치차단확인: 문안 ↔ 코드(어떤 값을 누구에게 보이나) 대조 · 플레이스홀더 검출 함수
13.4동의 — 필수/선택 분리 · 만14세 · 마케팅 분리·철회 · 결제 전 취소 규정 동의와 버전 기록차단확인: 가입 화면 · 결제 전 체크박스 · 동의 버전 열
13.5거래기록 5년 보존 vs 탈퇴·삭제 정책, 탈퇴 동선(§21의2)차단확인: 탈퇴 시 주문·결제 행 처리 · 보존 모양 결정
13.6판매자 불이행 보상(소비자분쟁해결기준)과 배상 주체, 연령 제한 상품의 확인 강제차단확인: 약관 조항 · 코드의 배상 집행 · 연령 제한이 주문에서 강제되나
13.7변호사 검토 — 질문 목록·발송일·회신이 한 곳에 기록된다차단(문안)확인: 기록 위치

14.1PG 심사 서류(사업자등록증 · 통판 신고증 또는 확인증 · 대표자 신분증 · 통장) + 실 도메인 서비스 URL차단확인: 서류 체크 · URL 에 약관·처리방침·사업자 정보
