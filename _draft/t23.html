빌링키를 받아서 매달 결제를 거는 것까진 금방 돼요. 문제는 첫 실패가 나는 날이에요. 카드 재발급, 한도 초과, 정지된 카드… 정기결제는 일반 결제보다 실패가 잦은데, 실패한 다음에 뭘 할지는 코드에 없는 경우가 많아요.

스케줄은 내 몫이에요

토스페이먼츠 자동결제는 빌링키로 결제를 승인하는 API 를 주지만, "매달 1일에 결제해 줘" 같은 스케줄은 해 주지 않아요. 내 서버의 스케줄러가 때가 되면 승인 API 를 불러야 해요. 그러니 재시도·실패 안내도 전부 내가 설계해야 합니다.

1. 스케줄러가 두 번 돌면 두 번 청구

배포하다 크론이 두 번 뜨거나, 오래 걸린 작업이 다음 실행과 겹치면 같은 달에 두 번 결제돼요. 결제 주기마다 주문번호를 "구독 ID + 기간"으로 고정하고 DB 에 유니크로 걸어 두세요. 토스는 주문번호가 고유해야 해서, 같은 번호로는 두 번 승인되지 않아요.

2. 재시도 — 바로 말고, 며칠 간격으로

  • 한도 초과 같은 실패는 실패 직후에 다시 해도 또 실패해요. 며칠 간격(예: 1일·3일·5일 뒤)으로 몇 번까지만 하세요.
  • 카드 정보가 바뀐 경우처럼 다시 해도 소용없는 실패는 재시도하지 말고, 바로 카드 변경을 안내하세요. 실패 응답의 코드·메시지를 저장해 두면 나눌 수 있어요.
  • 카드를 바꾸면 새 빌링키를 발급받고, 밀린 결제를 그 자리에서 한 번 시도하세요.

3. 실패 중에는 뭘 보여 줄까

정해 두지 않으면 둘 중 하나가 돼요. 실패해도 영원히 무료로 쓰거나, 한 번 실패하자마자 데이터까지 잠기거나요. 상태를 정상 → 결제 실패(유예) → 해지로 나누고, 유예가 며칠인지, 그동안 무엇을 쓸 수 있는지, 언제 끝나는지를 메일과 화면에 같은 문구로 알려 주세요.

4. 31일 가입자

1월 31일에 가입한 사람의 다음 결제일은 언제일까요? 2월 31일은 없으니 "말일"로 할지 "3월 3일"로 밀릴지 정해야 해요. 안 정하면 스케줄러가 그달을 그냥 건너뛰기도 해요. 서버 시간이 UTC 인지 한국 시간인지도 같이 확인하세요. 자정 기준 작업이 아홉 시간 어긋납니다.

5. 가격을 올리거나 무료 체험이 끝날 때

전자상거래법 시행령(2025년 2월 14일 시행)은 정기결제 대금이 오르거나 무료에서 유료로 바뀔 때, 바뀌기 전 30일 이내에 소비자 동의를 받고 취소 방법을 알리도록 하고 있어요. 가입할 때 받은 동의로 퉁칠 수 없고, "거부하지 않으면 동의" 방식도 안 돼요. 해지 버튼을 숨기는 것도 공정위가 말하는 다크패턴(취소·탈퇴 방해)에 들어가요.

정기결제 실패 체크리스트

  • 결제 주기마다 주문번호를 고정해 이중 청구를 막는다
  • 재시도는 며칠 간격으로, 횟수 상한을 둔다
  • 카드 문제면 재시도 대신 카드 변경을 안내한다
  • 실패 중 상태(유예)와 끝나는 날을 정해 두었다
  • 31일 가입자의 다음 결제일 규칙이 있다
  • 가격 인상·유료 전환은 30일 이내에 따로 동의받는다

마치며

정기결제는 첫 달엔 다 성공해요. 진짜 시험은 석 달째쯤 첫 카드 재발급 고객이 나올 때예요. 그날 서버가 조용히 넘어가지 않게, 실패 한 건만 일부러 만들어서 끝까지 따라가 보세요.
