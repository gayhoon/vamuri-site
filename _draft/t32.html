Next.js·Vite 로 만든 서비스를 Vercel 이나 Netlify 에 올리면 HTTPS 는 알아서 붙어요. 그런데 보안 헤더는 대부분 비어 있어요. 응답에 한 줄씩 붙이는 건데, 프레임워크 기본값에 안 들어 있거든요.

다섯 줄과 하는 일

  • Strict-Transport-Security — 브라우저가 이 사이트는 늘 https 로만 열게 해요. max-age=31536000; includeSubDomains
  • X-Content-Type-Options: nosniff — 올라온 파일을 브라우저가 멋대로 스크립트로 해석하지 않게
  • X-Frame-Options: DENY (또는 CSP frame-ancestors 'none') — 다른 사이트가 내 화면을 투명하게 끼워 넣고 버튼을 누르게 하는 클릭재킹 방지
  • Referrer-Policy: strict-origin-when-cross-origin — 다른 사이트로 넘어갈 때 주소 전체(토큰이 든 쿼리까지)가 넘어가지 않게
  • Content-Security-Policy — 어디서 온 스크립트만 실행할지 정해요. 스크립트 삽입(XSS)이 생겨도 피해를 줄이는 마지막 방어선

넣는 자리

  • Next.js — next.config.js 의 headers(), 또는 미들웨어에서 응답에 붙이기
  • Vercel — vercel.json 의 headers
  • Netlify — _headers 파일 또는 netlify.toml
  • Cloudflare — Transform Rules 의 응답 헤더

'반쯤 넣은' 함정

CSP 가 있다고 다 같은 CSP 가 아니에요. frame-ancestors 한 줄만 있는 CSP 는 화면 끼워 넣기만 막고 스크립트는 하나도 안 막아요. 헤더 검사 도구에서 "CSP 있음" 으로 나와도 script-src 나 default-src 가 들어 있는지 한 번 보세요.

CSP 를 처음 걸 땐 바로 켜지 말고 Content-Security-Policy-Report-Only 로 며칠 걸어 두세요. 결제창·분석 도구·폰트처럼 바깥에서 불러오는 게 깨지는지 콘솔에서 먼저 보고, 허용 목록을 채운 뒤 켜면 돼요.

확인하는 법

배포한 주소로 curl -sI https://내주소 를 해 보거나, 브라우저 개발자 도구 Network 탭에서 첫 요청의 응답 헤더를 보세요. 로컬에선 붙고 운영에선 빠지는 경우도 있어서 꼭 배포 주소로요.

보안 헤더 체크리스트

  • Strict-Transport-Security 가 있다 (max-age 1년)
  • X-Content-Type-Options: nosniff
  • X-Frame-Options 또는 CSP frame-ancestors
  • Referrer-Policy: strict-origin-when-cross-origin
  • CSP 에 script-src 나 default-src 가 들어 있다
  • 배포한 주소로 실제 응답 헤더를 확인했다

주소만 넣으면 이 헤더들을 한 번에 보여 주는 1분 점검도 있어요.

마치며

다섯 줄이라 10분이면 넣어요. 다만 CSP 는 서두르면 결제창이 안 뜨는 식으로 서비스가 깨지니까, 나머지 넷을 먼저 넣고 CSP 는 보고 모드로 천천히 가세요.
