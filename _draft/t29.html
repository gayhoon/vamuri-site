앱을 내고 일주일 뒤 큰 버그를 고쳐서 새 버전을 올렸어요. 그런데 옛 버전을 쓰는 사람이 한참 안 줄어요. 자동 업데이트를 꺼 둔 사람, 와이파이에서만 받는 사람이 생각보다 많거든요. 웹은 배포하면 끝인데, 앱은 사용자 폰에 옛 버전이 계속 살아 있어요.

스토어가 대신 강제해 주지 않아요

앱스토어와 구글 플레이 둘 다 "이 버전 아래는 못 쓰게" 같은 버튼은 없어요. 앱이 스스로 확인해야 해요. 그리고 여기서 함정 — 확인하는 코드가 이미 들어 있는 버전부터만 강제할 수 있어요. 1.0 에 이 코드가 없으면, 1.0 사용자는 영영 못 불러와요.

만드는 법 — 하루면 돼요

  • 최소 버전을 서버에 — DB 한 줄, 설정 파일, Firebase Remote Config 같은 곳에 min_version: 1.2.0 처럼 둬요. 앱을 새로 안 내고도 바꿀 수 있는 곳이어야 해요.
  • 켜질 때 비교 — 앱이 켜질 때 그 값을 받아서 내 버전과 비교해요. 문자열로 비교하면 "1.10" 이 "1.9" 보다 작게 나와요. 점으로 나눠서 숫자로 비교하세요.
  • 낮으면 막는 화면 — "새 버전이 나왔어요. 업데이트해 주세요" 와 스토어로 가는 버튼 하나. 안드로이드는 구글 플레이의 인앱 업데이트 기능으로 앱 안에서 바로 받게 할 수도 있어요.
  • 권장과 강제를 나누기 — 값을 둘로 두면 편해요. 권장 버전보다 낮으면 닫을 수 있는 안내, 최소 버전보다 낮으면 막는 화면.

조심할 것

  • 서버를 못 읽을 때 막지 않기 — 지하철에서 앱을 켰는데 확인 요청이 실패했다고 앱이 안 열리면 안 되죠. 못 읽으면 그냥 통과시키세요.
  • API 는 한동안 옛 버전도 — 강제 업데이트가 있어도 사용자가 업데이트하는 데 시간이 걸려요. 서버 API 를 바꿀 땐 옛 앱이 보내는 요청도 한동안 받아 주세요.
  • OTA 업데이트의 한계 — Expo 의 EAS Update 같은 OTA 로는 자바스크립트 코드는 바로 바꿀 수 있지만, 새 네이티브 라이브러리나 권한을 추가한 변경은 스토어에 새로 내야 해요. 그럴 때가 강제 업데이트가 필요한 순간이에요.

강제 업데이트 체크리스트

  • 앱이 켜질 때 '최소 버전' 을 서버에서 받아 온다
  • 최소 버전보다 낮으면 스토어로 가는 화면을 띄운다
  • 최소 버전 값은 앱 출시 없이 바꿀 수 있다
  • 서버를 못 읽으면 앱을 막지 않는다
  • API 를 바꿀 땐 옛 버전도 한동안 받아 준다
  • OTA 업데이트로 못 고치는 건 무엇인지 안다
