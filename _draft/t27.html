바이브코딩으로 만든 서비스는 대부분 해외 클라우드 위에서 돌아요. Vercel, Supabase, Firebase, OpenAI, Resend… 편하고 싸니까요. 그런데 회원 이메일이 미국 서버에 저장되는 순간, 한국 개인정보보호법으로는 개인정보 국외 이전이에요.

해외 서버를 쓰면 안 된다는 얘기가 아니에요

쓰셔도 돼요. 서비스 제공에 필요한 처리위탁·보관이라면, 법이 정한 내용을 처리방침에 공개하는 방법으로 이전할 수 있어요(개인정보보호법 제28조의8). 문제는 그 내용이 처리방침에 아예 없는 경우예요. 무료 템플릿으로 처리방침을 만들면 이 칸이 빠져 있기 쉬워요.

적어야 하는 다섯 줄

  • 무엇을 — 이전되는 개인정보 항목 (이메일, 이름, 결제 기록 등)
  • 어디로, 언제, 어떻게 — 이전되는 나라, 시기(예: 가입할 때·이용할 때마다), 방법(예: 네트워크를 통한 전송)
  • 누구에게 — 받는 회사 이름과 연락처 (예: Supabase Inc., 개인정보 문의 메일)
  • 왜, 얼마나 — 받는 회사의 이용 목적과 보유·이용 기간
  • 거부하려면 — 거부하는 방법·절차와, 거부하면 어떻게 되는지 (예: 서비스 이용이 어려워요)

내 서비스는 어디로 가고 있나 — 세는 법

개인정보가 지나가는 외부 서비스를 하나씩 적어 보세요. 생각보다 많아요.

  • 저장 — DB(Supabase·Firebase), 파일 저장소, 호스팅 서버 함수가 도는 리전
  • 보내는 곳 — 메일 발송(Resend·SendGrid), 문자, 푸시 알림
  • AI — 사용자가 쓴 글이나 사진을 AI API 로 보낸다면 그것도 이전이에요
  • 분석·오류 수집 — 분석 도구, 오류 추적 도구가 이메일이나 사용자 ID 를 같이 보내는지

각 서비스의 설정 화면에서 리전을 확인하세요. Supabase 는 프로젝트를 만들 때 서울 리전을 고를 수 있고, Vercel 은 서버 함수가 도는 리전을 프로젝트 설정에서 바꿀 수 있어요. 서울로 옮기면 적을 게 줄어요. 다만 AI API 처럼 고를 수 없는 곳은 그대로 적어야 해요.

국외 이전 체크리스트

  • 회원 정보가 저장·처리되는 서버의 나라를 확인했다
  • AI·메일·분석 도구로 보내는 개인정보도 셌다
  • 처리방침에 이전 항목·나라·시기와 방법을 적었다
  • 받는 회사 이름·연락처, 목적·보유 기간을 적었다
  • 거부하는 방법과 거부하면 어떻게 되는지 적었다
  • 가능하면 서울 리전을 골랐다

마치며

큰 회사 처리방침을 열어 보면 국외 이전 표가 꽤 길어요. 우리 서비스는 그만큼 길 필요는 없지만, 쓰는 서비스 수만큼은 줄이 있어야 해요. 표 하나 만드는 데 30분이면 충분합니다.
