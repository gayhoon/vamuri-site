"밤사이 인증 문자 3만 건" 같은 일은 예시로 든 숫자지만, 구조는 실제로 흔해요. 문자 인증은 요청 한 번 = 돈이라서, 누군가 인증번호 요청을 반복하면 그대로 청구서가 돼요.

왜 일어나나

  • 그냥 장난·봇 — 인증번호 보내기 API 가 열려 있으면 아무 번호나 넣고 계속 부를 수 있어요.
  • 문자 펌핑 — 비싼 해외 번호로 문자를 보내게 만들고, 그 통신 수익을 나눠 갖는 수법이 있어요. 해외 발송을 열어 두면 단가가 국내보다 훨씬 비싸서 피해가 커요.

막는 장치

  • 번호별 간격 — 같은 번호로 다시 보내기는 1분에 한 번.
  • 번호별 하루 상한 — 예를 들어 하루 5번. 넘으면 내일 다시.
  • IP·기기별 상한 — 번호를 바꿔 가며 보내는 걸 막으려면 요청한 쪽도 세야 해요.
  • 국가 제한 — 한국 서비스면 +82 만 허용. 해외가 필요하면 그때 국가를 골라 열기.
  • 봇 확인 — 상한에 가까워지면 캡차를 띄우는 것도 방법이에요.

Supabase·Firebase 의 전화번호 로그인도 기본 한도가 있지만, 서비스에 맞게 숫자를 직접 확인하고 조정하세요. 기본값이 생각보다 넉넉할 수 있어요.

마지막 안전망 — 돈 쪽에서 막기

코드에서 다 막았다고 생각해도, 발송 서비스(문자 API) 쪽에 일일 발송 한도와 예산 알림을 걸어 두세요. 코드에 구멍이 있어도 청구서가 무한히 커지지 않게 하는 장치예요.

문자 비용 체크리스트

  • 같은 번호로 다시 보내기는 1분에 1번
  • 같은 번호 하루 상한(예: 5번)
  • 같은 IP·기기 시간당 상한
  • 해외 번호는 꼭 필요할 때만 허용
  • 발송 서비스에 일일 한도·예산 알림
  • 발송량이 튀면 운영자에게 알림

마치며
