OpenAI 키를 .env 에 넣고 "환경변수니까 안전하겠지" 했는데, 막상 배포된 사이트에서 개발자 도구를 열면 키가 그대로 보이는 경우가 있어요. 범인은 보통 이름 앞에 붙은 한 단어예요.

NEXT_PUBLIC_ 은 "브라우저에 넣어 주세요" 라는 뜻

Next.js 는 NEXT_PUBLIC_ 으로 시작하는 환경변수를 빌드할 때 자바스크립트 파일 안에 글자 그대로 박아 넣어요. 그래야 브라우저에서 돌아가는 코드가 그 값을 쓸 수 있으니까요. 브라우저에 내려간 파일은 누구나 열어 볼 수 있죠.

다른 도구도 같은 장치가 있어요.

  • Vite — VITE_ 로 시작하는 값
  • Expo — EXPO_PUBLIC_ 으로 시작하는 값 (앱 파일 안에 들어가요)
  • Create React App — REACT_APP_ 으로 시작하는 값

"접두사 없으면 화면 코드에서 undefined 가 나와서" 접두사를 붙였다면, 그 순간 키가 공개된 거예요. 코딩 도구가 에러를 고치면서 접두사를 붙여 주기도 해서 더 헷갈립니다.

공개돼도 되는 키, 안 되는 키

  • 돼도 되는 것 — Supabase anon 키(RLS 가 켜져 있을 때), Firebase 웹 설정값, 지도 API 의 브라우저용 키(도메인 제한을 걸었을 때), 결제창을 띄우는 클라이언트 키
  • 안 되는 것 — OpenAI·Claude 같은 AI 키, 결제 시크릿 키, Supabase service_role 키, 문자 발송 키, DB 접속 주소

기준은 간단해요. 이 키로 돈이 나가거나, 남의 데이터를 열 수 있으면 서버에만 둡니다.

확인하는 법 — 5분

배포된 사이트를 열고 개발자 도구 → Sources(소스) 탭에서 전체 검색(맥은 ⌘⌥F)으로 sk-, secret, service_role 을 찾아보세요. 나오면 공개된 거예요.

나왔다면

  • 키를 새로 발급하고 옛 키를 끊으세요 — 코드에서 지우는 걸로는 부족해요. 이미 누군가 복사해 갔을 수 있어요.
  • 그 키를 쓰는 코드를 서버로 — Next.js 라면 Route Handler 나 Server Action, 그 밖엔 Supabase Edge Function 같은 서버 함수에서 부르고, 화면은 그 함수만 부르게 바꿉니다.
  • 사용량 상한 — AI·문자 API 는 콘솔에서 월 한도를 걸어 두면, 혹시 새도 청구서가 무한히 커지진 않아요.

앱도 마찬가지예요. iOS·안드로이드 앱 파일은 풀어 볼 수 있어서, 앱 안에 넣은 키는 공개된 것과 같아요.

공개 접두사 체크리스트

  • NEXT_PUBLIC_ · VITE_ · EXPO_PUBLIC_ 붙은 값엔 비밀이 없다
  • AI·결제·DB 관리자 키는 서버에서만 쓴다
  • 배포된 사이트 JS 에서 sk- · secret 을 검색해 봤다
  • 앱(iOS·안드로이드) 안에도 비밀 키를 넣지 않았다
  • 한 번이라도 공개됐던 키는 새로 발급하고 옛 키를 끊었다
  • AI·문자 같은 유료 API 에 사용량 상한을 걸었다

마치며

.env 는 "깃에 안 올리는 파일"이지 "숨겨 주는 금고"가 아니에요. 금고 역할은 서버가 합니다. 키 이름에 PUBLIC 이 들어가 있으면, 말 그대로 받아들이시면 돼요 ㅎㅎ

참고: Next.js Environment Variables 문서(Bundling Environment Variables for the Browser), Vite Env Variables 문서, Expo Environment variables 문서. 2026년 10월 기준.
