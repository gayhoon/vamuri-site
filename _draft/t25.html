출시하고 사흘째, 처음 보는 사용자에게 DM 이 와요. "결제 버튼 눌러도 아무 일도 안 일어나요." 서버 로그를 열어 보니 그 시간 로그는 이미 지워져 있고요. 혼자 만든 서비스는 이런 날이 꼭 와요.

큰 회사처럼 대시보드를 다 갖출 필요는 없어요. 첫 주엔 "내가 사용자보다 먼저 안다" 만 되면 충분해요.

1. 에러를 한곳에 모으기

화면(브라우저·앱)에서 난 에러는 서버 로그에 안 남아요. 사용자 폰에서 터지고 끝이죠. Sentry 같은 오류 추적 도구를 붙이면 화면 에러와 서버 에러가 한곳에 모이고, 처음 보는 에러가 생기면 메일이나 메신저로 알려 줘요. 무료 플랜으로 시작할 수 있어요.

붙일 때 하나만 더 — 소스맵을 올려 두세요. 안 그러면 에러 위치가 "main.3f2a.js 1번째 줄" 처럼 나와서 읽을 수가 없어요.

2. 사이트가 죽었는지 알기

몇 분마다 내 사이트 주소를 열어 보고, 안 열리면 알려 주는 무료 서비스가 여럿 있어요(업타임 모니터링). 홈 주소 하나, 로그인이나 API 주소 하나 정도 걸어 두면 돼요. 알림은 메일보다 폰 푸시나 메신저가 빨라요.

3. 돈과 가입은 따로

에러가 안 나도 문제인 경우가 있어요. 결제 승인이 실패했는데 화면은 "완료"로 넘어가거나, 인증 메일이 안 가서 가입이 멈추는 경우요. 결제 실패·가입 실패가 생기면 디스코드나 슬랙으로 한 줄 보내게 해 두세요. 웹훅 몇 줄이면 돼요. 하루에 가입·결제가 몇 건인지 아침에 한 줄 받는 것도 좋아요. 0 이 찍힌 날 뭔가 깨진 걸 알 수 있거든요.

4. 로그가 얼마나 남는지

호스팅 무료 플랜은 서버 로그를 짧게 보관하는 경우가 많아요. 내 플랜에서 로그가 몇 시간·며칠 남는지 확인하고, 짧으면 중요한 건 DB 나 로그 서비스에 따로 남기세요. 사용자가 "어제 저녁에요" 라고 할 때 볼 게 있어야 하니까요.

덤 — 사용자가 알릴 창구

화면 어딘가에 문의 메일이나 카카오톡 채널 같은 연락 창구를 두세요. 사용자가 알려 줄 길이 없으면 그냥 떠나요. 알려 주는 사용자는 정말 고마운 사람이에요.

첫 주 모니터링 체크리스트

  • 화면·서버 에러가 한곳에 모이고 알림이 온다
  • 사이트가 죽으면 몇 분 안에 폰으로 안다
  • 결제·가입 실패는 따로 알림이 온다
  • 로그가 며칠 남는지 내 플랜에서 확인했다
  • 사용자가 문제를 알릴 연락 창구가 화면에 있다
  • 알림이 너무 많지 않게 걸러 두었다

마치며

알림이 너무 많으면 결국 안 보게 돼요. 처음엔 "새로운 에러"와 "사이트 다운"과 "돈·가입 실패"만 울리게 두세요. 나머지는 일주일 지나고 늘려도 늦지 않아요.
